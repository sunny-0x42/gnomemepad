Guide & how it works

          

            gnomemepad is a meme launchpad on Gno.land Sapphire:
            fair launches, bonding-curve price discovery, then atomic graduation into a permanently locked CPMM pool.

2. Using the app

          

            

              
Markets

              
List of coins on the curve or already graduated. Open a card for chart, buy/sell, and graduation progress.

            

            

              
Create

              
Set name, symbol, and a create bond of at least 1 GNOT. No pre-mint to the creator — all tradeable float sells on the curve.

            

            

              
Trade

              
Buy sends GNOT for tokens. Sell returns tokens for GNOT. After graduation, trades use the locked pool (SwapBuy / SwapSell).

            

            

              
Portfolio

              
GNOT balance and meme token holdings for the connected (or view-only) address.

            

            

              
Creator

              
Coins you launched, accrued creator fees, and claim fees to your Adena wallet.

            

            

              
View-only

              
Paste any g1… address to browse. Create / Buy / Sell still require Adena to sign.

            

            

              
Profile

              
On-chain display name & bio (separate realm). Shown on market cards next to creators.

            

            

              
Rewards

              
Referral + check-in points on a separate points realm. Leaderboard is public.

            

          

        


        

          
Modular architecture

          

            Features live in separate packages so you can upgrade one without redeploying the whole pad.
          

          

            

              
hub

              
Registry of module paths (pad, profile, meta, points, legacy_*). UI resolves the active pad from hub.

            

            

              
padv4 (+ legacy)

              
Launch & trade. Markets filter: All / Active / Legacy. Create always uses the active pad.

            

            

              
profile

              
SetProfile / GetProfile — name, bio, URI per wallet.

            

            

              
meta

              
Token description, image, socials. First writer owns the entry for that pad+launch id.

            

            

              
points

              
Referrer once (+50 / +25), check-in (+5 / ~100 heights), leaderboard. Not tied to trade volume.

            

            

              
Trade UX

              
Client-side quotes + slippage % → minOut on padv4+ (legacy padv3 has no minOut args).

            

          

        


        

          
3. How the platform works

          

            

              01
              

                
Create (fair launch)

                
The creator pays a create bond. Supply is fixed; nothing is pre-minted to the team. Everyone buys on the same bonding curve.

              

            

            

              02
              

                
Bonding curve (virtual CPMM)

                
Price follows a virtual constant-product market (virtual GNOT × virtual tokens). Buys push price up; sells return tokens to the curve for GNOT.

              

            

            

              03
              

                
Graduation

                
When GNOT raised on the curve hits the threshold, the protocol atomically seeds a real CPMM pool and locks LP — no external DEX migration window.

              

            

            

              04
              

                
Locked pool

                
After graduation, trading uses the locked pool. LP cannot be withdrawn (permanent lock), reducing post-listing liquidity dumps.

              

            

          

          

            All market logic runs on-chain in a Gno realm (the factory is the market). The UI only reads state and submits wallet-signed transactions.
          

        


        

          
4. Curve pricing (how price is calculated)

          

            While a launch is on the bonding curve, price discovery uses a
            virtual constant-product AMM (CPMM) — the same family of math as Uniswap v2 / Pump-style curves,
            but with virtual reserves that start pre-seeded so the first buys are not free and price rises smoothly.
          


          
Invariant

          

            Virtual reserves always satisfy approximately:
          

          
k = Ru × Rt  (constant)

          
    
            
  • Ru — virtual ugnot reserve (quote)
    • 
            
  • Rt — virtual token reserve (base)
    • 
            
  • At create: Ru = 30 GNOT (30,000,000 ugnot), Rt ≈ 1.073B virtual tokens
    • 
          


          
Spot price (what the UI shows)

          

            Instantaneous price in GNOT per token is the ratio of virtual reserves:
          

          
P ≈ Ru / Rt   (ugnot per token)
price_GNOT = P / 1_000_000

          

            Market cap (FDV) on the UI ≈ price_GNOT × total_supply (1B tokens).
            Circ. mcap uses tokens sold so far instead of full supply.
          


          
Buy (GNOT in → tokens out)

          
    
            
  1. You send gross GNOT (ugnot) with the transaction.
    2. 
            
  2. Protocol takes the trade fee first (see Fees): net = gross − fee.
    3. 
            
  3. Net ugnot is added to the virtual ugnot reserve:
              
    Ru' = Ru + net_in
Rt' = k / Ru'
tokens_out = Rt − Rt'
    
            
    4. 
            
  4. You receive tokens_out; virtual reserves update to (Ru', Rt').
    5. 
          

          

            Larger buys move further along the curve → higher average price (slippage). Partial fills may apply if the buy would exceed remaining curve supply (800M).
          


          
Sell (tokens in → GNOT out)

          
    
            
  1. You send tokens back into the curve.
    2. 
            
  2. Virtual token reserve increases; ugnot reserve falls to keep k:
              
    Rt' = Rt + tokens_in
Ru' = k / Rt'
ugnot_out_gross = Ru − Ru'
    
            
    3. 
            
  3. Fee is applied on output; you receive net GNOT.
    4. 
          


          
Worked intuition

          

            

              
Early buys

              
Virtual ugnot is still near 30 GNOT and token side is large → low spot price. Small GNOT amounts buy many tokens.

            

            

              
Later buys

              
As real GNOT is absorbed into Ru, Rt shrinks → price rises. The same GNOT buys fewer tokens (slippage).

            

            

              
Graduation

              
When raised GNOT hits the threshold (50 GNOT testnet), the curve ends. Remaining seed tokens + raised liquidity open a real CPMM pool with permanently locked LP.

            

            

              
After graduate

              
Pricing uses the locked pool reserves instead of virtual curve reserves (SwapBuy / SwapSell) — still constant-product, but with real balances.

            

          


          
On-chain formulas (integer math)

          

            Implemented in ammmath.BuyTokens / SellTokens with overflow-safe integer division (floor). Dust stays with the curve/pool.
          

          
// Buy (net ugnot already after fee)
newVU = virtualUgnot + ugnotIn
newVT = (virtualUgnot * virtualToken) / newVU
tokensOut = virtualToken - newVT

// Sell
newVT = virtualToken + tokensIn
newVU = (virtualUgnot * virtualToken) / newVT
ugnotOut = virtualUgnot - newVU

        


        

          
5. GRC20 tokens & Gnoswap listing

          

            Each Create mints a real GRC20 token bound to the pad realm
            (Token.ID = padPkg.SYMBOL.seq). Buys mint to the buyer; sells burn.
            Holders can Transfer / Approve for external use (DEX).
          

          

            

              01
              

                
Create → GRC20

                
New launch registers a GRC20 ledger in the pad. No pre-mint to the creator; circulating supply grows only via curve buys.

              

            

            

              02
              

                
Graduate → listable

                
When raised hits the threshold, pad seeds a locked internal CPMM and sets GnoswapReady. The GRC20 already exists and is transferable.

              

            

            

              03
              

                
List on Gnoswap

                

                  Gnoswap pools are permissionless. After graduation, create a GNOT/token pool on Gnoswap
                  (seed liquidity from holders). Register metadata via
                  gno-token-resource
                  for full UI display.
                

              

            

          

          

            Pad pool and Gnoswap pool can coexist. Prices may diverge — arbitrage is expected.
            Automated Gnoswap pool creation (if/when chain APIs allow) can be wired later without changing the GRC20 mint model.

7. Fees & claims

          
    
            
  • 1.20% fee on every trade (buy/sell).
    • 
            
  • Of that fee: about 40% creator, 40% protocol, remainder stays with curve/pool (LP residual).
    • 
            
  • Creators claim fees under Creator (Adena signs ClaimCreatorFees).
    • 
            
  • Protocol claims via ClaimProtocolFees (treasury set at Init).
    •
